Eclipse to Web-CAT, and reading what comes back

A pipeline in three stations. On the left, an Eclipse window with a blue download arrow in it. First two checkboxes beneath it are ticked in orange — format, and javadocs — and an arrow draws across to the middle station, Web-CAT. Then a second arrow draws to the right, and the report itself is drawn on: a score bar and a dozen lines of code. Then two of those lines turn maroon and four turn pale pink, one after another, captioned failures, start here, and never run by your tests. Last, a note: pink inside your test classes costs nothing.

Do this on the projector rather than describing it — the first submission of the semester is the one that goes wrong. Import the demo project with the blue download arrow, submit to Web-CAT from inside Eclipse, then open the report and read it with them. If there is time, submit deliberately broken code first: a red report on the screen now is cheaper than a red report at midnight. The report shows a score summary, file details line by line, results from running your tests, code coverage, an estimate of problem coverage, and on projects, staff comments. Step 1 — format and finish the javadocs before you submit; they are graded, not decoration. Step 3 — red lines are failures, start there; pink lines are code your tests never ran. Eclipse’s own coverage view answers the same question without the round trip: clear it with the double-X on the coverage tab and re-run. The habit to install this week is submit early and often, and read the report every time.
