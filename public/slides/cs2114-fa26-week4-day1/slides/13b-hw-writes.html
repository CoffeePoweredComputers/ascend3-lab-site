The writes are five moves; every one changes numberOfEntries except rotate and reverse, and the problems say so. Step 1: add after a node (735) — two assignments, in that order: newNode.setNext(node.getNext()) first, then node.setNext(newNode); swap them and the rest of the chain is lost. A null node means add at the front; a null value means do nothing. Step 2: remove a node (781, 782) — one assignment, prev.setNext(curr.getNext()); the node is unreachable. If the node is firstNode, move firstNode instead; if it is not in the chain, do nothing. removeAll (682) is firstNode = null and count zero. Step 3: splice a chain in (786, 787) — find the other chain’s last node, count as you go; last2.setNext(node.getNext()) then node.setNext(first2). Concatenate (785) is the same with node = this chain’s last node. Empty cases: this chain empty, firstNode = first2; other empty, nothing. Step 4: rotate (783) — the picture is A B C D E with newHead D; the problem’s example is A to F with E. Find prev and last first; if prev is null (newHead is already first, or not in the chain) do nothing; otherwise last.setNext(firstNode), prev.setNext(null), firstNode = newHead. Partial reverse (784): cut after givenNode, reverse the front part with prev/curr/next, reattach the rest. Step 5: the LinkedBag four — add at the front is the add slide; toString is step 1’s walk; removeAll is firstNode = null; addLikeASet is contains, then add. Pick five: one from each move you find hard.
