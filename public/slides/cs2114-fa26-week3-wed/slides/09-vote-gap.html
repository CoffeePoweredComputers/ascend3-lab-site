What is the most efficient way to close the gap?

A peer-instruction question. On the left, the question stem — the most efficient approach to dealing with a gap left in an array after removing an entry would be to — over a drawing of an array of six cells holding ant, bee, a dashed empty cell at index 2, dog, eel and fox, with numberOfEntries equal to 6 above and the words index 2 was just removed below. On the right, the four ways to complete the sentence: A, replace the entry being removed with the first entry in the array and replace the first entry with null; B, shift subsequent entries and replace the duplicate reference to the last entry with null; C, replace the entry being removed with the last entry in the array and replace the last entry with null; D, replace the entry being removed with null. Nothing builds.

The most efficient approach to dealing with a gap left in an array after removing an entry would be to …

numberOfEntries = 6

  1. 0ant
  2. 1bee
  3. 2
  4. 3dog
  5. 4eel
  6. 5fox

index 2 was just removed

  1. replace the entry being removed with the first entry in the array and replace the first entry with null

  2. shift subsequent entries and replace the duplicate reference to the last entry with null

  3. replace the entry being removed with the last entry in the array and replace the last entry with null

  4. replace the entry being removed with null

Answer: C — copy the last entry into the gap, null the old last slot, count down one. One move whatever the size, and legal because a bag has no order: nothing has to stay where it was. A moves the gap instead of closing it — the first entry fills index 2 and index 0 is now the hole. B is correct but not efficient: every entry after the gap shifts one to the left, n moves instead of one; it is the answer a list would need, and the discussion usually turns on whether a bag needs it. D leaves null in the middle of the live entries, and every loop over 0 to numberOfEntries minus 1 — contains, getFrequencyOf, toString — now lands on a hole.
