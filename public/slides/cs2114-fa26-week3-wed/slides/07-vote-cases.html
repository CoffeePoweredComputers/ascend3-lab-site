Which implementation of contains could not be used?

A peer-instruction question about the ArrayBag class. On the left, the class’s two fields — an array of entries and a count of how many are in use — plus two given methods in full: getFrequencyOf, which loops over the array counting matches, and getIndexOf, a private helper that loops over the array and returns the index of the first match, or minus one if none is found. On the right, the bodies of four candidate implementations of contains, labeled A through D. A walks the array with a while loop and a found flag. B returns whether getIndexOf is greater than minus one. C returns whether a misspelled getFreuqencyOf is greater than zero. D walks the array with a while loop whose bound is less-than-or-equal-to numberOfEntries instead of less-than.

Answer: D — its bound, i <= numberOfEntries instead of i < numberOfEntries, lets i reach one past the last valid index. With 5 entries the valid indexes are 0 to 4; D's loop still runs the check at i = 5, and contents[5] is out of bounds — an ArrayIndexOutOfBoundsException, not just a wrong answer. A is a correct, if verbose, linear scan with a found flag. B correctly reuses getIndexOf: any non-negative index means a match turned up. Worth naming afterwards: C also could not be used as written — getFreuqencyOf is misspelled, so it does not compile — but D is the one built to be traced: the room can walk the index right off the end of the array and watch it happen.
