What does this array search print?

A peer-instruction question. On the left, a for loop that walks an array comparing each element to a searched value: on a match it sets a boolean found to true, and on every other iteration it resets found to false, with no early exit. On the right, the initial values — an eight-element int array ending in two hundred fifty then five hundred, a searched value of two hundred fifty, and found starting false — and under them four candidates for the printed output: found 250, not found, found 500, and the claim that an IndexOutOfBoundsException is thrown.

Search.java

  1. for (int i = 0; i < values.length; i++) {
  2. if (values[i] == searchedValue) {
  3. found = true;
  4. } else {
  5. found = false;
  6. }
  7. }
  8. if (found) {
  9. System.out.println("found " + searchedValue);
  10. } else {
  11. System.out.println("not found");
  12. }

initial values

  1. int[] values = { 3, 6, 10, 12,
  2. 100, 200, 250, 500 };
  3. int searchedValue = 250;
  4. boolean found = false;

  1. found 250

  2. not found

  3. found 500

  4. An IndexOutOfBoundsException is thrown

Answer: B — not found. The loop does reach i = 6, where values[i] is 250 and found is set true — but the else clause resets found on every non-matching iteration too, and i = 7 (500) is one more comparison after the match, so found ends the loop false. A is the trap: it assumes the match "sticks", which is exactly what the else overwrite prevents. C is not even a message the program can produce — a true found always prints "found 250", never "found 500". D is wrong because the loop guard i < values.length keeps every index in bounds. Worth naming afterwards: swapping the else for a break the moment found goes true, or dropping the else entirely, is the fix.
