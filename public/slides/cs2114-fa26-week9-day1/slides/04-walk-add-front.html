Adding at position 0 changes firstNode

A walkthrough of a list's add method under a program-counter bar: void add of int p and T x; Node newNode equals new Node of x; if p equals 0, newNode dot next equals firstNode, then firstNode equals newNode; else Node nodeBefore equals getNodeAt of p minus 1, newNode dot next equals nodeBefore dot next, nodeBefore dot next equals newNode; then numberOfEntries plus plus. On the right, a blue firstNode pill with the word null beside it, above an empty row where nodes will appear. Each node is a box with a data part and a next part. Step one: add of 0 and B on an empty list; a node holding B, next null, appears on the right, tinted orange and labelled newNode. Step two: p is 0, so the first branch runs. Step three: newNode dot next equals firstNode; B's next part is washed orange and stays null, because firstNode is null. Step four: firstNode equals newNode; the null beside firstNode is removed and an arrow from firstNode to B appears; the caption says a list that also keeps lastNode must set lastNode here too. Step five: add of 0 and A; a node holding A appears to the left of B. Step six: p is 0 again. Step seven: A's next part is washed orange, its null is removed and an arrow is drawn from A to B. Step eight: firstNode's arrow re-points from B to A; the list is A, B. Step nine: adding at position 0 writes two references, whatever the length of the list.

  2. Node newNode = new Node(x);
  3. if (p == 0) {
  4. newNode.next = firstNode;
  5. firstNode = newNode;
  6. } else {

This is add with a position, the method from the LinkedList Add video. The video draws it; the code is Carrano’s, with positions counted from 0 as the videos count them, and with newPosition shortened to p and newEntry to x. The list has one reference, firstNode. Step 1. add(0, B) runs on an empty list. The constructor makes a node with data B and next null. The orange tint marks newNode. Step 2. p is 0, so the first branch runs. Step 3. newNode.next = firstNode. firstNode is null, so B’s next is set to null, which it already was. Step 4. firstNode = newNode, so B is the first node, and the only one. Ask: if this class also kept a lastNode, what would lastNode have to be now? It has to refer to B as well. Keep that in mind for Vote 1. Step 5. add(0, A) creates a second node. Step 6. p is 0 again. Step 7. newNode.next = firstNode sets A’s next to B, the node that was first until now. Step 8. firstNode = newNode, so firstNode refers to A. The list is A, B. The order of steps 7 and 8 matters: if firstNode were set first, A’s next would be set to A. Step 9. Adding at position 0 writes two references and does not walk the chain, so its cost does not depend on the length. Next is a position in the middle, the else branch.
