Adding in the middle starts at the node before

The same add method under a program-counter bar. On the right, a list of three nodes holding A, B and C, linked left to right, with a blue firstNode pill referring to A. Step one: add of 2 and X; a node holding X, next null, appears below the chain between B and C, tinted orange and labelled newNode. Step two: p is 2, not 0, so the else branch runs. Step three: getNodeAt of 1 starts at firstNode; a blue ring labelled nodeBefore appears around A. Step four: the ring moves one node along to B. Step five: newNode dot next equals nodeBefore dot next; X's next part is washed orange and an arrow is drawn from X up to C. Step six: nodeBefore dot next equals newNode; B's arrow re-points from C down to X; the list is A, B, X, C. Step seven: lines 8 and 9 trade places in the editor, and the picture goes back to its state after step four: X's arrow is removed and B's arrow points at C again. Step eight: the line now in row 8, nodeBefore dot next equals newNode, runs first; B's arrow re-points to X, and C turns grey and is labelled unreachable, because nothing refers to it. Step nine: the line now in row 9, newNode dot next equals nodeBefore dot next, sets X's next to X itself; an arrow loops from X back to X. Step ten: set newNode dot next before nodeBefore dot next changes.

  1. void add(int p, T x) {
  2. Node newNode = new Node(x);
  3. if (p == 0) {
  4. newNode.next = firstNode;
  5. firstNode = newNode;
  6. } else {
  7. Node nodeBefore = getNodeAt(p - 1);
  8. newNode.next = nodeBefore.next;
  9. nodeBefore.next = newNode;
  10. }
  11. numberOfEntries++;
  12. }

add(2, X) on A, B, C creates a node holding X.

p is 2, not 0, so the else branch runs.

getNodeAt(p - 1) is getNodeAt(1). It starts at firstNode, which is A.

It moves one node along. nodeBefore refers to B, the node at position 1.

newNode.next = nodeBefore.next sets X’s next to C.

nodeBefore.next = newNode sets B’s next to X. The list is A, B, X, C.

Lines 8 and 9 trade places, and the same call runs again from step 4.

nodeBefore.next = newNode runs first and sets B’s next to X. Nothing refers to C now.

newNode.next = nodeBefore.next sets X’s next to X itself. C is lost.

Set newNode.next before nodeBefore.next changes.

The same add method, now the else branch. This is the drawing from the video’s “Adding a Node Between Adjacent Nodes”, where the video calls the two nodes prev and curr. Step 1. add(2, X) on A, B, C. X should end up at position 2, between B and C. Step 2. p is not 0, so the else runs. Step 3. getNodeAt(p - 1) is getNodeAt(1). It starts at firstNode, at A, and moves once per position. Step 4. One move, and it returns B. That is nodeBefore, the node at position 1. Step 5. newNode.next = nodeBefore.next. B’s next is C, so X’s next is set to C. Nothing in the list has changed yet. Step 6. nodeBefore.next = newNode sets B’s next to X. The list is A, B, X, C. Two writes, after the walk. Step 7. Now swap lines 8 and 9 and run the same call again from the point where nodeBefore is B. Step 8. nodeBefore.next = newNode runs first. B’s next is X now, and nothing refers to C any more. Step 9. newNode.next = nodeBefore.next reads B’s next, which is X, so X’s next is set to X. C and every node after it are lost, and anything that walks this list goes round X forever. Step 10. Set the new node’s next while nodeBefore.next still refers to the rest of the chain. This is also the homework problem Insert After Node. Next is the end of the list.
