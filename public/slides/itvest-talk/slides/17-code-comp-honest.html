Act III · skill 03 · the honest slide

Where does code comprehension fit?

the case for
Reading code is good practice for writing specs
EiPL asks students to describe code in their own words. That's spec writing in reverse — the same muscle. So even if we de-emphasize tracing code for its own sake, EiPL still earns its place.
the case against
Trace-and-predict is harder to justify now
When students mostly read model output rather than write loops themselves, the classical "predict what this loop returns" exercise loses some of its motivation. It's not useless — it's just no longer obvious it belongs early.

Where I land: at the intro level, code comprehension earns its place when it's in service of spec writing — not as a standalone goal.

To be clear: CS majors can't graduate without reading code. They can't. This is only a claim about what we do first.
