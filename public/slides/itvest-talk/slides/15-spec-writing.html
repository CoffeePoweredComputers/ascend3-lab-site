Why spec writing matters

A spec — prose, diagram, example, or test — is what a student actually owns once a model generates the code. The code itself is increasingly something the model produces in response.

Prompt Problems and decomposition diagrams are spec-writing activities by design. EiPL is one too — describing code is spec writing in reverse.

And — back to Dijkstra — the spec is where ambiguity has to be resolved. There's no compiler upstream anymore to catch it.

prose
"Return the maximum value in a list, or None if the list is empty."
diagram
[main]
 ├─ get_input
 ├─ validate
 └─ compute_max
tests
max_val([3, 7, 2]) == 7
max_val([]) is None
