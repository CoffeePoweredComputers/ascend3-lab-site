Activities · introduction

Two activities, two directions

The same code-generation-based grading loop powers two activities that face in opposite directions.

EiPL · code → description
Explain in Plain Language
Students see a piece of code and describe what it does. A correct description is one an LLM can turn back into functionally equivalent code.
stimulus
def f(xs):
  return max(xs) - min(xs)
expected response
"Returns the range of the list."
Prompt Problems · examples → description
Prompt Problems
Students see input/output examples and write the prompt that gets an LLM to produce code matching the behavior.
stimulus
f("hello")  →  "HELLO"
f("World")  →  "WORLD"
expected response
"Convert the input string to uppercase."

Both are graded by feeding the student's description to an LLM and checking whether the resulting code passes the unit tests.
