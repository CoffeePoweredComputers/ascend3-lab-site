Act III · what must be intro?

Three intro-level skills

If writing code isn't the focus of intro anymore, what should we teach instead? I'd argue three things — though one of them is contested.

01
Writing specifications
Saying what you want — in prose, diagrams, examples, or tests — clearly enough that a model can act on it.
02
Interpreting results
Reading what a model produces and deciding whether it's right, wrong, or confidently wrong.
03 · contested
Code comprehension
Reading code and predicting what it does. Still useful — but maybe as a means, not an end.

None of these is new. What's changed is which one we should spend the most time on — and the recognition that the spec, not the code, is what students actually need to get right.
