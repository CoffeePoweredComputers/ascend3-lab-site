Answer: D. Step 1 — lay out the array: 5 entries, so contents has valid indexes 0 through 4; name that range before touching the code. Step 2 — walk the search: the entry being looked for is not in the Bag, so the comparison misses at every real index, 0 through 4. Step 3 — the loop condition is i <= numberOfEntries, not i < numberOfEntries, so when i reaches 5 the loop checks 5 <= 5, which is true, and runs one more time; contents[5] is one past the last valid index, and the array throws ArrayIndexOutOfBoundsException. Step 4 — ring the while line and land the fix: swap <= for <. The rule underneath is the one worth them writing down: n entries live at indexes 0 through n−1, so the last valid index is always one less than the count, never equal to it. Plant: this exact off-by-one is the most common array bug they will write themselves this semester.
