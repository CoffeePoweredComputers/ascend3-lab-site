Which implementation of contains could not be used?

A peer-instruction question about the ArrayBag class. On the left, the class’s two fields — an array of entries and a count of how many are in use — plus two given methods in full: getFrequencyOf, which loops over the array counting matches, and getIndexOf, a private helper that loops over the array and returns the index of the first match, or minus one if none is found. On the right, four candidate implementations of contains, labeled A through D. A walks the array with a while loop and a found flag. B returns whether getIndexOf is greater than minus one. C returns whether getFrequencyOf is greater than zero. D walks the array with a while loop whose bound is less-than-or-equal-to numberOfEntries instead of less-than.

Answer: D — its bound, i <= numberOfEntries instead of i < numberOfEntries, lets i reach one past the last valid index. With, say, 5 entries the valid indexes are 0 to 4; D's loop still runs the check at i = 5, and contents[5] is out of bounds — an ArrayIndexOutOfBoundsException, and it fires exactly when the entry being searched for is not in the bag, since that is the only case where the loop runs that far. A is a correct, if verbose, linear scan with a found flag — i still increments every iteration, so it terminates. B correctly reuses getIndexOf: any non-negative index means a match turned up. C correctly reuses getFrequencyOf: any count greater than zero means the entry is present. D is the only one that cannot be used as written.
