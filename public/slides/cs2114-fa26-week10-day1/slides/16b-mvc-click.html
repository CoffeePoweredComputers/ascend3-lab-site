One click changes the model, and the model updates every view

A walkthrough under a program-counter bar. The editor's title bar holds the view's one line, e arrow controller dot onIncrementClicked. The code: the controller's onIncrementClicked, which calls model dot increment; the model's increment, which does data plus plus and calls notifyObservers; and notifyObservers, a for loop over observers calling o dot update of data. On the right, a card for the model reading Counter, data equals 0; two windows side by side, each titled Counter MVC Example with a label Counter colon 0 and an Increment button; and a console panel. Step one: an orange ring appears on the first window's button. Step two: the bar covers the controller. Step three: the bar covers increment and the model's data changes to 1. Step four: the bar covers notifyObservers; both window labels change to Counter colon 1 and the console prints Console View, Counter colon 1. Step five: the caption says the model never names a window or a console, and that this separation is what Project 3's Deliverable 2 has to show.

WindowView: e -> controller.onIncrementClicked()

  1. // CounterController
  2. public void onIncrementClicked() {
  3. model.increment();
  4. }
  5. // Counter, the model
  6. public void increment() {
  7. data++;
  8. notifyObservers();
  9. }
  10. private void notifyObservers() {
  11. for (Observer o : observers)
  12. o.update(data);
  13. }

The Increment button in the first window is clicked. Its listener calls controller.onIncrementClicked(). The view does not change the number.

The controller makes one call on the model, increment().

The model adds one to data, then calls notifyObservers().

The model calls update(1) on each of its three observers. Both windows and the console change. The second window was never clicked.

The model never names a window or a console. In Project 3, that separation is what Deliverable 2’s spec has to show.
