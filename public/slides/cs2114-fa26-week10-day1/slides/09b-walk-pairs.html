  2. for (int j = i; j < arr.length; j++) {
  3. System.out.println(arr[i] + arr[j]);
  4. }
  5. }

When i is 0, j runs from 0 to 3, so four lines are printed.

When i is 1, j runs from 1 to 3, so three more lines are printed.

When i is 2, j runs from 2 to 3, so two more lines are printed.

When i is 3, j is 3 only. Four entries print 4 + 3 + 2 + 1 = 10 lines.

The same program runs on an array of eight entries, and the count starts again at 0.

When i is 0, j runs from 0 to 7, so eight lines are printed.

When i runs from 1 to 7, the rows print 7 + 6 + 5 + 4 + 3 + 2 + 1 = 28 more lines, 36 in all.

Four entries print 10 lines and eight print 36. That is n(n + 1)/2, the sum from Vote 1, and it grows like n².

Answer: D — O(n²) [no PrairieLearn twin; by counting; confirm in Runestone’s results view]. The code is the vote’s program with 2-space indentation so it fits beside the grid. The grid has a cell for each pair i, j that the program prints: a row for each value of i and a column for each value of j. The difference from W5D1’s hasDuplicate is that j starts at i, not at i + 1, so the diagonal is printed too. Step 1. When i is 0, the inner loop runs four times. Step 2. When i is 1, three times. Step 3. Two times. Step 4. Once, for the pair 3, 3. Four entries, 10 prints. Step 5. The array has eight entries and the count starts again. Step 6. Row 0, eight prints. Step 7. The other rows, 28 more, 36 in all. Step 8. Ask what doubling the entries did to the count. 10 became 36, more than three times as many, and the ratio moves towards four as n grows. The count is n + (n − 1) + … + 1 = n(n + 1)/2, the same sum as the get loop in Vote 1, which is about n²/2. Constant factors are dropped, so it is O(n²). C, O(n log n), is the answer for students who see the inner loop getting shorter; it gets shorter by one each time, not by half. The next slide is Part 3.
