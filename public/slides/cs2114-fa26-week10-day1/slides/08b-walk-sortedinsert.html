insert(x) on a sorted chain, x = 10

  1. Node previousNode = null;
  2. Node currentNode = firstNode;
  3. while (currentNode != null &&
  4. currentNode.getData() < x) {
  5. previousNode = currentNode;
  6. currentNode = currentNode.getNext();
  7. }
  8. Node newNode = new Node(x, currentNode);
  9. previousNode.setNext(newNode);
  10. while (currentNode.getNext() != null &&
  11. currentNode.getNext().getData() < x)
  12. currentNode = currentNode.getNext();
  13. for (int d : list)

previousNode starts as null, and currentNode starts at firstNode, the node holding 3.

3 < 10, so previousNode is set to 3 and currentNode to 7.

7 < 10, so previousNode is set to 7 and currentNode to 12.

12 < 10 is false, so the loop stops. previousNode is on 7, the node before 12.

The new node holding 10 is created with its next set to currentNode, the node holding 12.

7’s next is set to the new node. The runner technique uses two references in one walk, so it is O(n).

The look-ahead technique tests currentNode.getNext(), so currentNode itself stops on 7. It uses one reference in one walk.

A foreach loop sets d to 3, then 7, then 12, then 20. It never gives you a node, so there is no next reference to set.

A singly linked node has no reference to the node before it. There is no reference from 20 back to 12.

  1. The foreach loop technique
  2. The look-ahead technique
  3. The runner technique
  4. The reverse transversal technique

The code uses the names from the 10.2 slides: previousNode and currentNode in the insertion sort, and the textbook’s getNodeBefore does the same walk with nodeBefore. The values are ints, so the test is getData() < x; the course code calls compareTo. The code leaves out the front case: if 10 were smaller than 3, previousNode would still be null after the loop, and the method would set firstNode to the new node instead. Step 1. previousNode is null and currentNode is on 3. Step 2. 3 < 10, so both references move one node. Step 3. 7 < 10, so both move again. Step 4. 12 < 10 is false and the loop stops. currentNode is on the first node that is not smaller, and previousNode is on the node before it, which is the node whose next has to change. Step 5. The new node is created with its next set to 12. Step 6. 7’s next is set to the new node. One walk, so O(n). This is the runner technique, option C. Step 7. The look-ahead technique, option B, is a second walk from firstNode. It keeps one reference and tests the node after it, so the loop stops with currentNode on 7. The insert is then currentNode.setNext(new Node(x, currentNode.getNext())). Also one walk, so O(n). The homework problem x709, Find Node Before, writes findNodeBefore with either technique, and x734 names both. Step 8. Option A. A foreach loop over the list gives you the values, 3, 7, 12, 20, one at a time. It never gives you a node, so there is no next to change. Step 9. Option D.
