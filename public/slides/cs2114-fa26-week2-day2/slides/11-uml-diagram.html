PRACTICE 1 · CREATE A CHILD CLASS

Turn this diagram into the Student class

A UML class diagram of two classes, built in four steps. First, on the left, the Person box inks in: name, age and heightInCM, a three-argument constructor, three getters and toString. Second, an arrow draws from right to left, from Student's side to Person's edge. Third, on the right, the Student box grows in with an orange edge: studentID and school, a five-argument constructor, and getters for both new fields. Last, the caption: the arrow means Student extends Person; Person is already written for you, write Student.

Step 1 — Person inks in. Read its box once: three fields, a three-argument constructor, three getters, toString. This one is written for you. Step 2 — the arrow draws from Student up to Person; say that the direction matters: the child points at the parent. Step 3 — Student grows in on the orange edge: the one you write. Read the diagram out loud once as a sentence: a Student is a Person that also knows a student ID and a school. Then ask what is missing from Student's box that a Student object still has — the answer is everything in Person's box, which is the whole reason to inherit. Step 4 — the caption. Give them four or five minutes before showing the code. Plant, last line before advancing: Person is already written for you — write Student.
