PRACTICE 1 · NULL POINTER

Which line throws, and which line is the cause?

A walkthrough of the eight-line method. On the left the code, with a program-counter bar on the running line; on the right, the heap. Line 2 puts a personA pill on the heap with the word null under it and no arrow, because null is not an address; nothing is drawn where a Person would be. Line 3 puts a personB pill below it and grows a Person box with age 10, name Ben and grade F; personB’s arrow draws to it. On line 4 a blue line under the heap reads personA is null — nothing to ask, and the null under personA turns blue. Then the program stops: the counter bar goes dark, the null turns maroon, line 5 is marked as never run, and a panel stamps the exception exactly as Java prints it: a NullPointerException, cannot invoke Person.getAge because personA is null, at line 4. Last, the answer lands on the code itself: a maroon ring around line 4 tagged threw, then an orange ring around line 2 tagged the cause, and the caption reads: the trace names the line that dereferenced null, never the line that put it there.

The trace names the line that dereferenced null, never the line that put it there.

Answer: line 4 throws, line 2 is the cause — and that gap is the whole lesson: the stack trace names the line that dereferenced null, never the line that put null there, and on a real project those two can be in different files. Step 1 — line 2: personA gets a pill and, under it, the word null. Point at the empty space to its right: no arrow, because null is not an address, and no box, because no Person was made. Step 2 — line 3: personB gets a real Person, age 10; the arrow draws. (This question’s Person takes age, name, grade, in the constructor order PrairieLearn’s Person uses — Ben’s "F" is a letter grade, not a gender.) Step 3 — line 4: ask what personA.getAge() is actually asking the machine to do: go to the object personA points at. It points at nothing. The null under the pill goes blue — this is the reference being followed. Step 4 — the program counter goes dark, the exception stamps, line 5 is marked never runs. Read the trace aloud: at Main.ageMath(Main.java:4). It says 4, and only 4 — and, since JDK 14, it names personA too. Step 5 — the two rings: maroon on line 4, it threw; orange on line 2, it is the cause. The trace hands you the first; you walk backwards to find the second. Plant: “Next one: the null comes in from outside.”
