Which test reaches 100% branch coverage?

A peer-instruction question. On the left, a method returning 1 for a positive number, minus 1 for a negative number and 0 otherwise — three branches. On the right, four candidate tests: one checking 5 and minus 3; one checking 10, 0 and 2; one checking minus 9 and 0; and one checking 7, minus 2 and 0.

the method under test

  1. public int getSign(int x) {
  2. if (x > 0) {
  3. return 1;
  4. } else if (x < 0) {
  5. return -1;
  6. } else {
  7. return 0;
  8. }
  9. }

  1. assertEquals(1, getSign(5));

    assertEquals(-1, getSign(-3));

  2. assertEquals(1, getSign(10));

    assertEquals(0, getSign(0));

    assertEquals(-1, getSign(2));

  3. assertEquals(-1, getSign(-9));

    assertEquals(0, getSign(0));

  4. assertEquals(1, getSign(7));

    assertEquals(-1, getSign(-2));

    assertEquals(1, getSign(0));

Answer: D — 7, minus 2 and 0 are the only set that enters all three branches. A never reaches the else. B looks like three cases but 10 and 2 are both positive, so it never reaches the negative branch. C never reaches the positive one. The sting in D is worth the whole question: its last assertion expects 1 where the method returns 0, so the test fails — and still has 100% coverage. Coverage asks “did this line run”, not “is it right”, which is exactly why Project 1 asks for a normal case and a bad-input case per method.
