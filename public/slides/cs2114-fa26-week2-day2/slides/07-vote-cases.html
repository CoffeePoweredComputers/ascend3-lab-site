Which test covers every case of this method?

A peer-instruction question. On the left, a factory method that returns null when the name is the empty string and a new Hokie otherwise. On the right, four candidate test methods, each two assertions long: assertNull with assertNotNull; assertEquals against null with assertEquals against the string Hannah; assertEquals against null with assertNotEquals; and assertNull twice, the second one negating its argument.

the method under test

  1. public Hokie createHokie(String name) {
  2. if (name.equals("")) {
  3. return null;
  4. }
  5. return new Hokie(name);
  6. }

  1. assertNull(createHokie(""));

    assertNotNull(createHokie("Hannah"));

  2. assertEquals(null, createHokie(""));

    assertEquals("Hannah", createHokie("Hannah"));

  3. assertEquals(null, createHokie(""));

    assertNotEquals("Hannah", createHokie("Hannah"));

  4. assertNull(createHokie(""));

    assertNull(!createHokie("Hannah"));

Answer: A — the method has exactly two cases — empty name gives null, anything else gives an object — so a covering test needs one assertion for each, and assertNull/assertNotNull say precisely that. B compares a Hokie to a String, which is never equal; C asserts the object is not "Hannah", which is true but tests nothing (assertNotEquals lives in org.junit.Assert, JUnit 4.11+ — a JUnit-3 TestCase like vote 1’s would need a static import of org.junit.Assert.assertNotEquals, so assume JUnit 4 here); D does not compile, because you cannot apply ! to an object reference. Worth naming afterwards: C is the dangerous one, since it passes.
