Step through slowly — line 5 is the whole lecture: watch e1's arrow swing. Other orderings of the same two answer lines are equally correct. The kicker used to end “one line at a time”. Captions before trimming — 1: “new Employee() puts an object on the heap; e1 holds a reference to it.” 3: “setID travels through e1’s reference and writes into the object.” 5: “The assignment copies the reference, not the object — and the 123 object just became unreachable.” 6: “A fresh object breaks the sharing: e1 points somewhere new.” Talk cue: the orange box is the one your code made — the same orange as the previous slide’s dashed “id = 555” requirement and as the gutter numbers of your two lines. Per step — 1: an object on the heap, e1 holds it. 2: a second object, a second reference. 3: the write goes through e1. 4: same through e2. 5: the swing — the reference is copied, the object is not; 123 is garbage. 6: a new object, in orange — the requirement becoming real. 7: 555 lands; e2’s box never moved.
