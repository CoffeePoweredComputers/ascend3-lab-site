RECALL · WEEK 2 · TYPES

What is printed?

A recall question on inheritance and polymorphism. On the left, an editor: class Shape with a method area returning 0.0; class Circle extends Shape with a private field r, a constructor taking r, and an overriding area returning pi times r times r; then two lines: Shape s equals new Circle of 2.0; System out println of s dot area. On the right, a small UML pair — a Circle box with a hollow-headed arrow up to a Shape box — and four options: A, 0.0 — s is declared a Shape; B, 12.566370614359172 — the object is a Circle; C, does not compile, Shape has no field r; D, ClassCastException at run time. On the one step, the four answers return under both columns, A, C and D struck through in turn and B left standing.

Shape and Circle, then two lines

  1. class Shape {
  2. double area() { return 0.0; }
  3. }
  4. class Circle extends Shape {
  5. private double r;
  6. Circle(double r) { this.r = r; }
  7. @Override double area() { return Math.PI * r * r; }
  8. }
  9. Shape s = new Circle(2.0);
  10. System.out.println(s.area());

  1. 0.0 — s is declared a Shape

  2. 12.566370614359172 — the object is a Circle

  3. Does not compile: Shape has no field r

  4. ClassCastException at run time

  1. the object’s type picks the method
  2. Circle’s area runs
  3. s.area() compiles; s.r would not
  4. an upcast does not throw
Answer: B — 12.566370614359172. Show of hands, then the answer. s is declared as Shape, so the compiler checks that Shape has an area method; at run time the object is a Circle, so Circle’s area runs. The variable’s type determines what you may call; the object’s type determines which method runs. A assumes the declared type picks the method. C confuses the two: s.r would not compile, s.area() does. D: assigning a Circle to a Shape variable is an upcast, always legal; ClassCastException is the other direction.
