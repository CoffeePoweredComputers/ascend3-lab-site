Which implementation of contains could not be used?

A recall of a Week 3 peer-instruction question about the ArrayBag class. On the left, the class’s two fields — an array of entries and a count of how many are in use — plus two given methods in full: getFrequencyOf, which loops over the array counting matches, and getIndexOf, a private helper that loops over the array and returns the index of the first match, or minus one if none is found. On the right, the bodies of four candidate implementations of contains, labeled A through D. A walks the array with a while loop and a found flag. B returns whether getIndexOf is greater than minus one. C returns whether a misspelled getFreuqencyOf is greater than zero. D walks the array with a while loop whose bound is less-than-or-equal-to numberOfEntries instead of less-than. On the one step, four short verdicts return under both columns, A, B and C struck through in turn and D left standing.

Answer: D. Its condition i <= numberOfEntries lets i reach one past the last valid index; contents at that index is null or out of bounds, so the method throws. Show of hands, then the answer. One eight-point test question is in this topic: add, remove or contains on the array bag. A is a correct linear scan. B correctly reuses getIndexOf. C is misspelled and does not compile, so it is also unusable; D is the one to trace. Next: contains on a chain is a traversal to null.
