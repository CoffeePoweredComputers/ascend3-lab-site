RECALL · WEEK 2 · TESTING & EXCEPTIONS

Which test covers every case of this method?

A recall of a Week 2 peer-instruction question. On the left, a factory method that returns null when the name is the empty string and a new Hokie otherwise. On the right, four candidate test methods, each two assertions long: assertNull with assertNotNull; assertEquals against null with assertEquals against the string Hannah; assertEquals against null with assertNotEquals; and assertNull twice, the second one negating its argument. On the one step, the four answers return under both columns as short verdicts, B, C and D struck through in turn and A left standing.

the method under test

  1. public Hokie createHokie(String name) {
  2. if (name.equals("")) {
  3. return null;
  4. }
  5. return new Hokie(name);
  6. }

  1. assertNull(createHokie(""));

    assertNotNull(createHokie("Hannah"));

  2. assertEquals(null, createHokie(""));

    assertEquals("Hannah", createHokie("Hannah"));

  3. assertEquals(null, createHokie(""));

    assertNotEquals("Hannah", createHokie("Hannah"));

  4. assertNull(createHokie(""));

    assertNull(!createHokie("Hannah"));

  1. one assertion per case
  2. a Hokie is never equal to a String
  3. passes but tests nothing
  4. does not compile
Answer: A. The method has two cases — empty name returns null, anything else returns an object — so a covering test needs one assertion per case. Show of hands, then the answer. Four test questions are in this topic: which cases a set of tests covers, a test for a method that throws, a test for equals, and checked versus runtime exceptions. Ask the exception variant: if createHokie threw IllegalArgumentException for the empty name, what does the test look like? (A try block that fails if the call returns, with the pass in the catch; or JUnit’s expected attribute.) B compares a Hokie to a String, never equal. C passes but tests nothing. D does not compile.
