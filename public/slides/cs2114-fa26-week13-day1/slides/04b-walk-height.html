The height of a tree is its number of levels

The course’s example tree from the last slide on the left, measured level by level. Steps one to four: a grey band washes across each level in turn, labelled level 1 to level 4; level 1 holds A, level 2 holds B and C, level 3 holds D, E and H, and level 4 holds F and G. Step five: an orange path draws on from A through B and E to F, and a card under the drawing reads: height equals the number of levels, which equals 1 plus the edges from the root to the deepest node. The path has three edges, so the height is 4. Step six: on the right a second tree grows in, J, K, L and M, each the right child of the one above, one per level; it also has height 4. Step seven: at the top right a single node in a card; a single node is a tree of height 1, and CE 13’s height method counts this way. Step eight, in maroon: height counts levels, and two trees of the same height can hold very different numbers of nodes.

height = number of levels = 1 + edges from the root to the deepest node

Level 1 holds the root, A.

Level 2 holds the root’s children, B and C.

Level 3 holds D, E and H.

Level 4 holds F and G, so the tree has four levels.

The path from the root to the deepest node, F, has three edges. The height is one more than that, 4, which is the number of levels.

This tree has four nodes on four levels, each the right child of the one above it, so it also has height 4.

A single node is a tree of height 1, which is how CE 13’s height() counts.

Height counts levels, and two trees of the same height can hold very different numbers of nodes.

This is how the votes, the module checkpoints and CE 13 count height. Steps 1 to 4: count the levels. Level 1 is the root, A. Level 2 is B and C. Level 3 is D, E and H. Level 4 is F and G. Step 5: the deepest node is F (G is as deep). The path from A to F has three edges, and the height is one more than the number of edges, 4. That is the same as the number of levels, and it is the wording the votes use: the height of a tree is 1 more than the number of edges from the root to the deepest node. Step 6: a tree that leans all the way to the right, J, K, L, M, also has four levels and height 4. Step 7: a single node is a tree of height 1, and an empty tree, null, has height 0. CE 13’s height() counts the same way, a leaf is 1. One caution: the ProgrammingTrees slide in the module has a getHeight that counts edges instead, so a leaf is 0 there and this tree would be 3. The votes, the checkpoints and CE 13 all count levels, and so does this deck. Step 8: height alone does not say how many nodes a tree has; the two trees here have the same height and different numbers of nodes.
