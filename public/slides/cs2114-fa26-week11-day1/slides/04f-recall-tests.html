Which test reaches 100% branch coverage?

A recall of a Week 2 peer-instruction question. On the left, a method getSign that returns 1 for a positive number, minus 1 for a negative number and 0 otherwise: three branches. On the right, four candidate tests: A checks 5 and minus 3; B checks 10, 0 and 2; C checks minus 9 and 0; D checks 7, minus 2 and 0. On the one step, four short verdicts appear under both columns, A, B and C struck through in turn and D, all three branches, left standing.

the method under test

  1. public int getSign(int x) {
  2. if (x > 0) {
  3. return 1;
  4. } else if (x < 0) {
  5. return -1;
  6. } else {
  7. return 0;
  8. }
  9. }

  1. assertEquals(1, getSign(5));

    assertEquals(-1, getSign(-3));

  2. assertEquals(1, getSign(10));

    assertEquals(0, getSign(0));

    assertEquals(-1, getSign(2));

  3. assertEquals(-1, getSign(-9));

    assertEquals(0, getSign(0));

  4. assertEquals(1, getSign(7));

    assertEquals(-1, getSign(-2));

    assertEquals(1, getSign(0));

  1. else never runs
  2. no negative
  3. no positive
  4. all three branches
Answer: D — 7, minus 2 and 0 are the only set that runs all three branches [key from the source deck W2D2 08]. Show of hands, then the answer. getSign has three branches: x greater than 0, x less than 0, and the else. A tests 5 and minus 3, so the else never runs. B tests 10, 0 and 2; 10 and 2 are both positive, so the negative branch never runs. C tests minus 9 and 0, so the positive branch never runs. D tests 7, minus 2 and 0, one input per branch. D’s last assertion expects 1 where getSign(0) returns 0, so that test fails, and it still has 100% branch coverage. Coverage says which lines ran, not whether the expected values are right.
