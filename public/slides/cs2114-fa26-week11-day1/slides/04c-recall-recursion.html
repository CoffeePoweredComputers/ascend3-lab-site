In which order does displayChain print the chain?

A recall of a Week 7 peer-instruction question, quoted in reading order. Left, two editors. The first is headed given fields and holds two lines: private Node firstNode, with the comment reference to first node, and private int numberOfEntries. The second is headed and the following code and holds six lines: private void displayChain of Node curr; if curr is not null, call displayChain of curr's next, then print curr's data; two closing braces. Right, the question: indicate how the private helper member method would print a non-empty chain. Then three options, each led by a maroon disc with its letter: A, in order; B, in reverse order; C, neither. On the one step, three short verdicts appear under both columns, A and C struck through in turn and B, the last node prints first, left standing.

Given fields:

  1. private Node firstNode; // Reference to first node
  2. private int numberOfEntries;

And the following code:

  1. private void displayChain(Node curr) {
  2. if (curr != null) {
  3. displayChain(curr.getNext());
  4. System.out.println(curr.getData());
  5. }
  6. }

Indicate how the private helper member method would print a non-empty chain

  1. A

    In order

  2. B

    In reverse order

  3. C

    Neither

  1. print after the call
  2. last node first
  3. always reversed
Answer: B — in reverse order [ASSUMED by tracing in the source deck W7D2 10; the key is not in the Runestone paste; confirm in Runestone’s results view. The PL twin u09q03_recursion_linkedchain_c, with the print above the call, is keyed “In order”, which agrees]. Show of hands, then the answer. The recursive call comes before the print. displayChain(A) calls displayChain(B) before it prints A, B calls C before it prints B, and so on to the null after the last node, which returns without printing. Then the calls return in the opposite order: the last node prints first and A prints last. A is the answer for the other version, with the print above the call. C is wrong because the order is the same every time: every node prints once, last to first. This topic had two questions on Test 2. Next: queues and deques.
