What does adding an entry cost?

A recall of a Week 5 peer-instruction question. Under the title, the question stem in muted type: what is the time complexity for adding an entry to an array-based bag ADT that is not a fixed length. Below it, two panels side by side. Left, a drawing of the bag’s array: the line contents dot length equals 6, numberOfEntries equals 6, then six cells holding ant, bee, cat, dog, eel and fox at indexes 0 to 5, with no free cell. Right, the four options as rows, each led by a maroon disc with its letter: A, O of 1; B, O of n; C, O of n caret 2; D, Negligible. On the one step, four short verdicts appear under both panels, A, C and D struck through in turn and B, O of n because a full array is copied, left standing.

Answer: B — O(n) [key from the source deck W5D1 06; the PL twin u08q08_efficiency_arraybag_c is this question verbatim]. Show of hands, then the answer. Read the question out: a bag on an array that is not a fixed length. The drawing is six of six, so the next add has no free cell. The bag makes a new, larger array and copies all six entries into it before it adds, and copying n entries is n moves. Big-O names the worst case, so add is O(n). A is the cost only when the array has a free cell: write the entry at index numberOfEntries and add one to the count. C would mean n moves for each of n entries; the copy happens once for the one add, so it is n moves, not n times n. D is not a time complexity at all. This topic had four questions on Test 2.
