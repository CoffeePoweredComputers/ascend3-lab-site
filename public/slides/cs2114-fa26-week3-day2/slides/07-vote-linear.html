Which operation takes linear time?

A peer-instruction question. On the left, the question stem — suppose you are designing an unsorted ArrayBag class which has fields contents and numberOfEntries; which of the following would require linear, O of n, time in the worst case, even with the most efficient implementation — over a drawing of the bag’s array: six cells holding ant, bee, cat, dog, eel and fox at indexes 0 to 5, a dashed empty cell at index 6 past the count, and numberOfEntries equals 6 above. Two short lines under the drawing gloss the terms: linear time, the steps grow with the count; constant time, the same few steps at any count. On the right, the four options: A, removing a random element from the bag; B, checking whether the bag contains a given entry; C, adding a new entry to the bag; D, returning the current size of the bag. Nothing builds; there is no step.

Answer: B. The question as printed: “Suppose you are designing an unsorted ArrayBag class which has fields contents and numberOfEntries. Which of the following would require linear (O(n)) time in the worst case, even with the most efficient implementation?” Before the groups start, say what linear means in one breath — the number of steps grows with the count, against constant, the same few steps at any count; O(n) gets its proper introduction in the Week 5 efficiency module, so this is a preview. Two things groups trip on. A: “a random element” means remove() with no argument, an unspecified entry, and vote 1 just showed that as one move; removing a specific entry by value would need contains first, and that is linear. C: add is one write at contents[numberOfEntries]; the array growing when full is the caveat, not the rule.
