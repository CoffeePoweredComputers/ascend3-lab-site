Answer: B — and deal the three one-move answers first, so the room hears why each is constant before the linear one lands. Step 1 — D: size is one read of numberOfEntries; the array is never touched. Step 2 — C: add writes the first free slot, contents[numberOfEntries], and counts up — one write at any count. If someone asks about a full array: it has to grow, and that copy is the one time add costs more; the question says most efficient implementation, so the everyday case is the answer. Step 3 — A: remove() of an unspecified entry is exactly the move vote 1 walked — read the last entry, null its slot, count down. No search, because any entry will do; that is what “unsorted” and “random” buy. Removing a specific entry by value would be contains plus that move, so linear — name it, because that reading is what makes groups pick A. Step 4 — B: contains(x) compares x with entries until one matches, and when x is not in the bag it compares with all n of them; the worst case grows with the count, so linear, and the sweep across the row is the cost. Plant: the count is the bag — everything a bag can do in one move, it does at the end. Only “is it here?” has to look. Week 5 puts names on the two shapes: O(1) and O(n).
