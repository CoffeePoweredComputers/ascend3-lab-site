The video’s cases for 10 slots. With backIndex 0, (0 + 1) % 10 is 1.

(1 + 1) % 10 is 2. For backIndex 0 to 8, the % does not change the sum.

(5 + 1) % 10 is 6.

(8 + 1) % 10 is 9.

(9 + 1) % 10 is 10 % 10, which is 0.

enqueue(K) changes backIndex from 9 to 0. K goes into slot 0, which a dequeue emptied.

enqueue(L) changes backIndex from 0 to 1.

Five dequeues remove E to I. frontIndex is now 9.

One more dequeue removes J. (9 + 1) % 10 is 0, so frontIndex is 0.

After slot 9, the next index is 0, for both frontIndex and backIndex.

This is the module’s enqueue. The only change from the last slide is the percent sign. Under the method is the matching line from dequeue, which uses the same arithmetic. Steps 1 to 5 build the table from the video: the value the line computes for a few values of backIndex when the array has 10 slots. For 0 to 8, the remainder after dividing by 10 is the sum itself. For 9 the result is 0. Step 6: enqueue K. backIndex was 9, the last slot, and becomes 0. K goes into slot 0, which a dequeue emptied two slides ago. Step 7: L goes into slot 1. Step 8: five dequeues. frontIndex changes from 4 to 9. Step 9: one more dequeue, and the same arithmetic sets frontIndex to 0. Step 10: the array is still a row of slots in memory; the two indices go from slot 9 to slot 0. In the video the array in this table is called queue; in the class code it is contents, and the deck uses contents. The next slide shows the problem when every slot is full.
