A QUEUE ON AN ARRAY · MOVE THE FRONT

Dequeue moves frontIndex, not the entries

A walkthrough of two methods under a program-counter bar. Left, dequeue: front is read from contents at frontIndex, that slot is set to null, frontIndex goes up by one, front is returned. Middle, enqueue of x: backIndex goes up by one and x is written at contents at backIndex. Right, a counter labelled moves. Below, a ten-slot array holding A to E in slots 0 to 4, a blue pill labelled frontIndex above slot 0 and a blue pill labelled backIndex below slot 4. Step one: slot 0 takes a blue edge and the counter reads 1. Step two: A fades. Step three: the frontIndex pill moves to slot 1. Step four: the caption says one move for one dequeue. Step five: the backIndex pill moves to slot 5 and F grows in there. Step six: the backIndex pill moves on to slot 9 while G, H, I and J grow into slots 6 to 9. Step seven: B, C and D fade and the frontIndex pill moves to slot 4. Step eight: the bar returns to the backIndex line of enqueue, and the caption says that slots 0 to 3 are empty but the next backIndex is 10, and there is no slot 10.

dequeue, moving frontIndex

  1. T dequeue() {
  2. T front = contents[frontIndex];
  3. contents[frontIndex] = null;
  4. frontIndex = frontIndex + 1;
  5. return front;
  6. }

enqueue, moving backIndex

  1. void enqueue(T x) {
  2. backIndex = backIndex + 1;
  3. contents[backIndex] = x;
  4. }

front = contents[frontIndex] reads A. The read is one move.

contents[frontIndex] = null clears slot 0.

frontIndex is now 1. B is the front, and B is still in slot 1.

One move per dequeue, for any number of entries.

enqueue(F) sets backIndex to 5 and puts F in slot 5.

Four more enqueues put G, H, I and J in slots 6 to 9. backIndex is 9.

Three more dequeues remove B, C and D. frontIndex is 4.

Slots 0 to 3 are empty, but the next backIndex + 1 is 10, and there is no slot 10.

The module’s design, without the % for now. The entries stay in their slots. Two indices give the slots of the front entry and the back entry, both inclusive. Step 1: the method reads the front, A. That is one move. Step 2: slot 0 is set to null. Step 3: frontIndex goes up by one. The pill moves; the entries do not. B is now the front, and B is still in slot 1. Step 4: a dequeue is one move for any number of entries; the shifting version on the last slide took five. Step 5: enqueue F. backIndex goes up by one and F is written there. Step 6: four more enqueues, and backIndex is 9, the last slot. Step 7: three more dequeues. frontIndex is 4 and slots 0 to 3 are empty. Step 8: the next enqueue would set backIndex to 10. There is no slot 10, although four slots are free. Ask the class where the next entry should go. The next slide uses % to send it to slot 0.
