A QUEUE ON AN ARRAY · FULL OR EMPTY?

One unused slot makes full and empty different

A walkthrough of the module's three tests, which appear as code lines one at a time under a program-counter bar. Below them, a ten-slot array with a frontIndex pill above slot 0 and a backIndex pill below slot 9, and a counter labelled entries. Step one: the empty test appears, frontIndex equals equals backIndex plus 1, mod contents dot length; for a new queue, 9 plus 1 mod 10 is 0, so it is empty. Step two: enqueue A; the backIndex pill moves from slot 9 back to slot 0 and A grows in. Step three: B to I grow into slots 1 to 8 and the backIndex pill moves to 8. Step four: J grows into slot 9, the backIndex pill moves to 9, all ten slots wash orange and the counter reads 10; the empty test passes on a full queue. Step five: the caption says full and empty give the same two numbers. Step six: J fades, slot 9 is hatched in grey as unused, the backIndex pill moves back to 8, and the full test appears: frontIndex equals equals backIndex plus 2, mod contents dot length, which holds. Step seven: the empty test now fails. Step eight: A to H fade, the frontIndex pill moves to slot 8, the hatch goes, and the one-entry test appears: frontIndex equals equals backIndex. Step nine: the caption says that one unused slot makes full and empty different, so a queue of capacity 9 uses an array of 10.

the three tests from the module’s wrap-up

  1. // empty
  2. frontIndex == (backIndex + 1) % contents.length
  3. // full
  4. frontIndex == (backIndex + 2) % contents.length
  5. // one entry
  6. frontIndex == backIndex

A new queue has frontIndex 0 and backIndex 9. (9 + 1) % 10 is 0, so the empty test is true.

enqueue(A) changes backIndex from 9 to 0.

B to I go into slots 1 to 8. backIndex is 8.

J goes into slot 9. frontIndex is 0 and backIndex is 9, so the empty test is true for a full queue.

Full and empty have the same two index values. The tests cannot tell them apart.

With slot 9 unused, the queue is full at nine entries. (8 + 2) % 10 is 0, so the full test is true.

(8 + 1) % 10 is 9, not 0, so the empty test is now false.

Eight dequeues leave only I. frontIndex and backIndex are both 8.

This slide answers how the queue can tell full from empty. The code under the bar is the three tests from the module’s wrap-up video. Each test appears when it is first used. Step 1: a new queue. The constructor sets frontIndex to 0 and backIndex to contents.length minus 1, which is 9. The empty test: 9 plus 1, mod 10, is 0. That equals frontIndex, so the queue is empty. Step 2: enqueue A. backIndex changes from 9 to 0. Step 3: B to I go into slots 1 to 8. Step 4: J goes into the last slot. With ten entries, frontIndex is 0 and backIndex is 9. These are the values the queue started with, and the empty test is true. Step 5: if every slot can be used, full and empty have the same index values. Step 6: the module never uses the last free slot. The queue is full at nine entries, slot 9 stays empty, and full has its own test, with plus 2. Step 7: the empty test is false for the full queue. Step 8: eight dequeues leave one entry, and frontIndex equals backIndex. Step 9: this is why the constructor allocates initialCapacity plus 1 slots. A queue of capacity 9 uses an array of 10. Two remarks if there is time. The wrap-up also mentions a different design with a size field, which needs no unused slot. The module’s enqueue calls ensureCapacity first; when the full test is true, it copies the entries in queue order into an array twice as long, starting at slot 0.
