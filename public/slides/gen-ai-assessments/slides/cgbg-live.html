ONE CORE IDEA · TWO OPEN QUESTIONS

What else can the stimulus be?

beyond code and input/output pairs — what else shows students what to elicit?

What can the process tell us?

what to capture while students work with the LLM — and how it folds into the grade

  • Smith IV & Zilles, ITiCSE 2024, Smith IV, Denny & Fowler, L@S 2024
[~3min · 9 clicks] GenAI moves the skill from writing code to specifying and explaining it — so how do you grade a natural-language answer at scale? Code generation based grading. (1) The student's text — here a prompt — types in. (2) An LLM generates code from it. (3) That code runs against ordinary unit tests. (4) Pass or fail comes back as feedback — in seconds. (5) Everything fades back: what prompt prompts the prompt? (6) We could show students a segment of code and ask them to explain what it is doing — and infer that a good explanation is one that generates code that passes the unit test suite. (A two-line function fades in, replacing the question.) (7) Or show students input/output pairs and have them infer the operation being done, then generate a prompt that generates code that passes the tests. (Pairs replace the code.) Each of these tests, in its own way, a student's ability to reverse engineer or to create a prompt, respectively. (8) The demo blurs back — one mechanism, two open questions. First: what other stimuli beyond code and input/output pairs could indicate what students should elicit from the LLM? (9) Second: thinking back to output vs process — what data from the collaboration itself might we collect, and how do we fold it into the assessment?
