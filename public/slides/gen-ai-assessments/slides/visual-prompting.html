The prompt doesn’t have to be text

Generate a program, then test it

Behavioral test suite

  • the word set never collapses early
  • a guessed letter narrows the set
  • the game ends on the last word

Or judge the drawing against a rubric

  • each responsibility gets its own box
  • the loop reaches every part of the game
  • no box decides when the game ends — returned as feedback

[~60s · 4 clicks] In the vein of new autograders that could grade other competencies: multimodal models let us ask students to produce visual artifacts and assess those artifacts directly. Here's the kind of artifact we mean — a student's drawn decomposition of a word-guessing game. (1) A multimodal model reads the photograph as-is — no transcription step, no context about the assignment. (2) Route one: the model generates a runnable program from the drawing, and that program runs against a behavioral test suite. The drawing is graded by whether the design it describes actually works. (3) Route two: no program at all — the model judges the drawing itself against a rubric, and what the rubric catches goes back to the student as written feedback. (4) The demo blurs back — nothing here is specific to decomposition diagrams: an ER diagram becomes a schema you can query, a UML diagram becomes objects you can instantiate. (If asked about the pilot: 133 intro Python students, 50 minutes, one sheet of paper — 81.2% of diagrams had their function structure fully extracted, r = .776 between functions drawn and functions generated.)
