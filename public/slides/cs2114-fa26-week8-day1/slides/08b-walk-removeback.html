Answer: D — Removing from a deque with one item [key from the PrairieLearn twin u10q07_linkeddeque_tracing_b; confirm in Runestone]. Walk it on the same two-node deque as removeFront. Step 1 — back = getBack(): B. Step 2 — lastNode moves back one node, to A, using prev; this is why the deque has prev. Step 3 — A is not null, so the else. Step 4 — setNext(null): the new back node has nothing after it, and B is gone. Step 5 — return B. Step 6 — removeBack() on the deque with one node. Step 7 — lastNode becomes A’s prev, and the only node has no prev: null. Step 8 — this is the case the question asks about: the test is true exactly when the node we just removed was the only one. Step 9 — firstNode = null: both ends are null, an empty deque. Step 10 — return A. Step 11 — C: call it once more on the empty deque. getBack() throws first, so line 4 is never reached; and even if it did not, lastNode is already null before the method starts, so lastNode.getPrev() would be a NullPointerException. Step 12 — A: a deque that holds anything has a back as well as a front, so “only at the front” describes nothing. B: a linked deque grows one node at a time and is never full; full is an array idea, Wednesday’s. Step 13 — D. Next: Vote 2.
