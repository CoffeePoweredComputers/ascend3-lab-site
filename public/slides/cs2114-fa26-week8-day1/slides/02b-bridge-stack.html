Before Fall Break we used the call stack. Today we keep the chain from Week 5 and change one thing about it. Step 1. In Week 7 each method call pushed a frame on the call stack, and each return popped it. fact(1) was the last frame pushed and the first one popped. A stack is last in, first out. Step 2. In Week 5 we stored a stack on a linked chain. The class had one reference, topNode, to the first node. push added a node at that end and pop removed the node at that end, so one reference was enough. Step 3. A queue is first in, first out. It adds at the back and removes at the front, so it works at both ends of the chain. The reference to the first node is now called firstNode, and the class keeps a second reference, lastNode, to the last node. The nodes are the same Node class as in Week 5. lastNode is the only new thing in Part 1. Step 4. This table is the comparison from the end of the module’s deque video. A stack adds and removes at the front, which is the top. A queue adds at the back and removes at the front. A deque, a double-ended queue, adds and removes at both ends; that is Part 2. Each one also has a method that reads without removing: peek for the stack, getFront for the queue, getFront and getBack for the deque. Part 1 starts with enqueue on a linked queue.
