A LINKED QUEUE · WHY lastNode

Without lastNode, every enqueue walks the whole chain

Two short pieces of code on the left. The first, without lastNode: Node curr equals firstNode; while curr dot getNext is not null, curr equals curr dot getNext; then curr dot setNext of newNode. The second, with lastNode: lastNode dot setNext of newNode; lastNode equals newNode. On the right, a queue of six nodes, A to F, with a firstNode pill pointing at A and a lastNode pill pointing at F, and under it two large counters of nodes visited: one in maroon for the code without lastNode, one in blue for the code with it. Step one: a blue ring labelled curr appears on A; the maroon counter reads 1. Steps two and three: the ring moves to B, then C; the counter reads 2, then 3. Step four: the ring moves on to F; the counter reads 6, and the loop stops because F's next is null. Step five: F's next part is washed orange: the one write, after six visits. Step six: the ring goes; with lastNode, F is reached in one visit, its next part is written, and the blue counter reads 1. Step seven: lastNode equals newNode, ready for the next enqueue. Step eight: O of 1, because of one extra reference.

without lastNode: find the back

  1. Node curr = firstNode;
  2. while (curr.getNext() != null) {
  3. curr = curr.getNext();
  4. }
  5. curr.setNext(newNode);

with lastNode (04)

  1. lastNode.setNext(newNode);
  2. lastNode = newNode;

Without lastNode, enqueue has to find the back. curr starts at firstNode: 1 node visited.

A’s next is not null: curr steps to B. 2 visited.

C: 3 visited.

D, E, F: 6 visited. F’s next is null, so the loop stops.

Then one write: F links to the new node. Six visits for one link; 1,000 nodes, 1,000 visits.

With lastNode the back is one reference away: one visit, the same write.

lastNode = newNode: it is ready for the next enqueue.

O(1) because of one extra reference.

Why does the class keep lastNode at all? The video says enqueue is O(1) “with use of lastNode reference”; this slide shows what it costs without it. The code on top is the non-empty part of an enqueue that only has firstNode. Step 1 — curr starts at the front; that is one node visited. Steps 2 and 3 — the loop steps curr forward while there is a next node: B, C. Step 4 — and on to F, six visits; F’s next is null, so curr is the back. Step 5 — only now the one write that enqueue is for. With n nodes this is n visits, every time: O(n), the Week 5 word. Step 6 — with lastNode we already know where the back is: one visit, the same write. Step 7 — and lastNode moves, so the next enqueue is one visit too. Step 8 — one extra reference turns O(n) into O(1). The same idea is behind the deque in Part 2. Next: Part 2.
