A LINKED QUEUE · WHY lastNode

Without lastNode, every enqueue visits every node

Two short pieces of code on the left. The first, without lastNode: Node curr equals firstNode; while curr dot getNext is not null, curr equals curr dot getNext; then curr dot setNext of newNode. The second, with lastNode: lastNode dot setNext of newNode; lastNode equals newNode. On the right, a queue of six nodes, A to F, with a firstNode pill pointing at A and a lastNode pill pointing at F, and under it two large counters of nodes visited: one in maroon for the code without lastNode, one in blue for the code with it. Step one: a blue ring labelled curr appears on A, and the maroon counter reads 1. Steps two and three: the ring moves to B, then C, and the counter reads 2, then 3. Step four: the ring moves to F and the counter reads 6. The loop stops because F's next is null. Step five: F's next part is washed orange. This is the one write, after six visits. Step six: the ring is removed. With lastNode, F is reached in one visit, its next part is written, and the blue counter reads 1. Step seven: lastNode equals newNode. Step eight: one extra reference makes enqueue O of 1.

without lastNode: find the back

  1. Node curr = firstNode;
  2. while (curr.getNext() != null) {
  3. curr = curr.getNext();
  4. }
  5. curr.setNext(newNode);

with lastNode (04)

  1. lastNode.setNext(newNode);
  2. lastNode = newNode;

Without lastNode, enqueue has to find the back node. curr starts at firstNode, so 1 node is visited.

A’s next is not null, so curr is set to B. 2 nodes visited.

curr is set to C. 3 nodes visited.

curr is set to D, then E, then F. 6 nodes visited. F’s next is null, so the loop stops.

curr.setNext(newNode) writes one link after six visits. With n nodes it takes n visits.

With lastNode, the back node is one reference away. That is one visit and the same write.

lastNode = newNode, so the next enqueue also takes one visit.

One extra reference makes enqueue O(1).

Why does the class keep lastNode? The video says enqueue is O(1) “with use of lastNode reference”. This slide shows the cost without it. The code on top is the non-empty part of an enqueue that has only firstNode. Step 1. curr starts at the front node, which is one node visited. Steps 2 and 3. The loop sets curr to the next node while there is one: B, then C. Step 4. curr is set to D, E and F, for six visits. F’s next is null, so curr is the back node. Step 5. The one write that enqueue needs happens only now. With n nodes this is n visits on every call, which is O(n) in the Week 5 terms. Step 6. With lastNode the back node is already known. That is one visit and the same write. Step 7. lastNode is assigned the new node, so the next enqueue is also one visit. Step 8. One extra reference changes enqueue from O(n) to O(1).
