Empty: both references are null. All four expressions are true.

One node: both references point at it. A, B and C say false, as they should. D says true.

Two nodes: all four are false.

  1. (firstNode == null) && (lastNode == null)
  2. (firstNode == null)
  3. (lastNode == null)
  4. (firstNode == lastNode)
Answer: D — (firstNode == lastNode) [key from the PrairieLearn twin u10q07_linkeddeque_tracing_c; confirm in Runestone]. The question asks which one does NOT work in all cases, so check every expression against every state of a deque. Three states are enough: empty, one node, more than one. Step 1 — empty: both references are null. A is true, B is true, C is true, and D, null == null, is true too. So far all four work. Step 2 — one node: firstNode and lastNode both refer to that node. It is not empty, and A, B and C all say false. D compares the two references, they are the same node, so D says true: it calls a deque with one item empty. This is the state from the very first enqueue and from the last removal in Vote 1. Step 3 — two nodes: everything is false, D included, so D only fails at exactly one node, which is why it is easy to miss when testing. Step 4 — D. B is the one the video’s queue uses; C works too, because in a correct deque the two references are null together. Next: Part 3, this week’s work.
