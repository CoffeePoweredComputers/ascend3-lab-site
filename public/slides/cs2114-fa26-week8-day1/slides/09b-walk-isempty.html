Answer: D — (firstNode == lastNode) [key from the PrairieLearn twin u10q07_linkeddeque_tracing_c; confirm in Runestone]. The question asks which expression does NOT work in all cases, so check every expression against every state of a deque. Three states are enough: empty, one node, and more than one node. Step 1. In the empty deque both references are null. A, B and C are true, and D, null == null, is also true. All four are correct so far. Step 2. With one node, firstNode and lastNode both refer to that node. The deque is not empty, and A, B and C are false. D compares the two references, which refer to the same node, so D is true. D reports a deque with one item as empty. This is the state after the first enqueue and before the last removal in Vote 1. Step 3. With two nodes all four are false, D included. D is wrong only at exactly one node, so a test that skips the one-node case does not find it. Step 4. The answer is D. B is the test the video’s queue uses. C also works, because in a correct deque the two references are null at the same time. Next is Part 3, this week’s work.
