RECURSION · NO BASE CASE

Without a base case, the calls never stop

The same method and call stack, with only main on the stack. Press one: the three base-case lines, if n equals 1, return 1, and the closing brace, are struck through and turn grey; the caption says take the base case out and run the same call, fact of 3. Presses two to four: fact of 3, fact of 2 and fact of 1 each grow a new frame on top, the one below turning grey to wait. Press five: fact of 0 grows in above the top of the stack’s box. Press six: fact of minus 1 and a column of dots grow in above it; n only gets smaller and nothing ever returns. Press seven: the box edge turns maroon and the word StackOverflowError appears beside the stack in maroon. Press eight: the stack clears, the strike-through lifts, and the code is labelled: lines 2 to 4 tinted blue, the base case, which stops the calls; line 5 tinted orange, the recursive case, which calls itself on a smaller n.

fact: n! = n × (n − 1)!

  1. int fact(int n) {
  2. if (n == 1) {
  3. return 1;
  4. }
  5. return n * fact(n - 1);
  6. }

Take the base case out. Run the same call again: fact(3).

fact(3) calls fact(2), as before.

fact(2) calls fact(1).

fact(1) used to stop. Now nothing checks n, so it calls fact(0).

fact(0) calls fact(-1). n only gets smaller and never reaches 1 again.

Every call adds a frame. None of them ever returns, so none comes off.

Java runs out of room for frames: StackOverflowError.

Base case, lines 2–4: stops the calls.

Recursive case, line 5: calls itself on a smaller n.

What makes it stop? Take the base case out and see. Step 1 — lines 2 to 4 are gone; the method still compiles, it just always calls itself. Step 2 — same call, fact(3); it calls fact(2). Step 3 — fact(2) calls fact(1). Step 4 — fact(1) used to answer 1. Now nothing checks n, so it calls fact(0). Step 5 — fact(0) calls fact(-1); n keeps getting smaller and never comes back to 1. Step 6 — every call is a new frame, and no call ever returns, so no frame ever comes off. Step 7 — the stack has a fixed amount of memory; when it is full, Java throws StackOverflowError. If you see that in your homework, look for a missing or unreachable base case. Step 8 — so every recursive method has two parts: a base case that answers without calling itself, which stops the calls, and a recursive case that calls itself on a smaller problem, a smaller n, so the calls get closer to the base case.
