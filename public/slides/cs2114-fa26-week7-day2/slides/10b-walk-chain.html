Reverse order: the print is below the call

A walkthrough of displayChain on the chain A, B, C from two slides before, under a program-counter bar. On the right, the chain with a blue ring on the node the running call is looking at, the call stack as boxes stacked from the bottom up, each showing curr with a blue arrow to its node, and a white plate labelled output. Step one: displayChain is called with A; curr is not null. Steps two to four: before printing anything, each call calls displayChain on curr's next, so boxes for B, C and null appear in turn, the ring moves along the chain, and each box below is marked waiting on line 3. Step five: curr is null, the if is false, and that call returns without printing. Step six: the call for C picks up on the line after its call and prints C. Step seven: its box fades and the call for B prints B. Step eight: the call for A prints A. Step nine: the last box fades, the output reads C, B, A on three lines, and the three options appear under the code with A and C struck through and B, in reverse order, left standing.

displayChain, called as displayChain(firstNode)

  1. private void displayChain(Node curr) {
  2. if (curr != null) {
  3. displayChain(curr.getNext());
  4. System.out.println(curr.getData());
  5. }
  6. }

curr refers to A. Not null, so the if runs.

The first line in the if is the call on the rest, starting at B. A’s call waits on line 3 and prints nothing yet.

B’s call does the same: it calls on the rest, starting at C, and waits.

C’s call calls on its next: null.

curr is null: the if is false and the call returns. The empty chain prints nothing.

C’s call picks up on the line after its call: it prints C.

C’s call comes off. B’s call picks up and prints B.

A’s call picks up and prints A.

Below the call, so on the way back: C B A. Put it above the call, as in show, and it prints A B C.

Answer: B — in reverse order [ASSUMED by tracing; confirm in Runestone. The PL twin with the print above the call, u09q03_recursion_linkedchain_c, is keyed “In order”]. Same chain, same picture as show. Step 1 — displayChain is called with the first node, A; curr is not null, so the if runs. Step 2 — the first line inside the if is the call on the rest, so A’s call calls on B and waits on line 3. Nothing printed. Step 3 — B’s call does the same, on C. Step 4 — C’s call calls on null. Step 5 — curr is null, the if is false, the call returns. The empty chain prints nothing: that is the base case, even though the code never says return. Step 6 — C’s call picks up on the line after its call and prints C. Step 7 — B. Step 8 — A. Step 9 — C, B, A: reverse order. A is what show printed, with the print above the call. C, neither, would need some node to be skipped or printed twice; every call prints its own node exactly once. Next: Part 3, writing one of these yourself.
