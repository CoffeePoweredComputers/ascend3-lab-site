AFTER THE CALL · THE SAME WALK

print(n) below the call: it runs on the way back

The same five-line method and the same call stack drawing as the slide before. Step one: the line print n moves down below the line count of n minus 1; the two lines swap places. Step two: count of 3 is called and its box appears. Steps three to five: count of 3 calls count of 2, which calls count of 1, which calls count of 0; a box appears on top each time and the box below is marked waiting on line 3; nothing is printed. Step six: n is 0, so count of 0 returns and its box fades. Steps seven to nine: count of 1 picks up on the line after its call and prints 1; then its box fades and count of 2 prints 2; then count of 3 prints 3. Step ten: count of 3 finishes. The output reads 1 2 3. Step eleven: the rule: above the call runs on the way in, below the call runs on the way back.

count(n), print below the call

  1. void count(int n) {
  2. if (n == 0) { return; }
  3. print(n);
  4. count(n - 1);
  5. }

called as count(3)

One change: print(n) moves below the call. Same call, count(3).

count(3) is called: n = 3, not 0.

No print first now: count(3) calls count(2) straight away and waits on line 3.

count(2) calls count(1) and waits. Still nothing printed.

count(1) calls count(0). Four frames, and the output is empty.

n is 0: the base case returns. Its frame comes off.

count(1) picks up on the line after its call: print(n) prints 1.

count(1) is done and comes off. count(2) picks up after its call and prints 2.

count(2) comes off. count(3) picks up and prints 3.

count(3) finishes. Output: 1 2 3, all of it printed on the way back.

Above the call: on the way in. Below the call: on the way back.

Same method, one change. Step 1 — print(n) moves below the recursive call; the two lines swap places. Same call: count(3). Step 2 — count(3) is called; n is 3, not 0. Step 3 — the first thing it does now is call count(2), and it waits on line 3. Nothing printed. Step 4 — count(2) calls count(1) and waits. Step 5 — count(1) calls count(0). Four frames and an empty output. Ask: when will anything print? Step 6 — count(0) is the base case and returns; its frame comes off. Step 7 — count(1) picks up where it was waiting, on the line after its call, and that line is the print: 1. Step 8 — count(1) is done and comes off; count(2) picks up and prints 2. Step 9 — count(3) prints 3. Step 10 — done: 1 2 3. Same calls in the same order, opposite output. Step 11 — the rule for the whole hour: above the call runs on the way in, below the call runs on the way back. Next: the peer instruction routine and two votes on exactly this.
