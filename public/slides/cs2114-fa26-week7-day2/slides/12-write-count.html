Count the nodes of a chain, one question at a time

A recursive method written one line per question, then run. Left, an editor that starts with only the header int count of Node curr and its closing brace, and a list of three questions under it. Step one: question 1, when do I stop?, appears, and the line if curr is null, return 0 is written. Step two: question 2, what is the smaller problem?, and the line int rest equals count of curr's next. Step three: question 3, what do I do with its answer?, and the line return 1 plus rest. On the right, the chain A, B, C ending in null with a blue ring on the node the running call is looking at, and the call stack under it. Steps four to seven: count is called on A, then on B, C and null, a box appearing for each with the one below marked waiting on line 3. Step eight: curr is null, so that call returns 0; a blue pill reading 0 moves down into the box for C and the null box fades. Steps nine to eleven: each box returns 1 plus what it got, so pills reading 1, 2 and 3 move down one box at a time; the last one, 3, drops below the stack as the answer.

count(curr), called as count(firstNode)

  2. if (curr == null) { return 0; }
  3. int rest = count(curr.getNext());
  4. return 1 + rest;
  5. }

When there is no chain left. curr == null is the empty chain, and it has 0 nodes.

The rest of the chain, from curr.getNext(). The same method counts it.

Add 1 for this node to the count of the rest.

Run it: count(A). curr is not null.

count(A) calls count on the rest, from B, and waits on line 3.

count(B) calls count(C) and waits.

count(C) calls count on null and waits.

The empty chain returns 0. It goes back to count(C) as rest.

count(C) returns 1 + 0 = 1 to count(B).

count(B) returns 1 + 1 = 2 to count(A).

count(A) returns 1 + 2 = 3. The answers came back up: 0, 1, 2, 3.

Writing a recursive method from three questions. The example is counting the nodes of a chain, which is not one of the homework problems. Step 1 — question 1, when do I stop? When there is no chain left: curr == null. An empty chain has 0 nodes, so return 0. Step 2 — question 2, what is the smaller problem? The rest of the chain, which starts at curr.getNext(). Trust the same method to count it, the way show trusted itself to show the rest. Step 3 — question 3, what do I do with its answer? Add 1, for this node. Three lines, three questions. Now run it. Step 4 — count(A); curr is not null. Step 5 — line 3 calls count on the rest, from B, and count(A) waits there. Steps 6 and 7 — the same for B and C; C’s next is null. Step 8 — count(null) is the base case and returns 0; the 0 goes back down into count(C), which was waiting on line 3, and becomes rest. Step 9 — count(C) returns 1 + 0 = 1. Step 10 — count(B) returns 2. Step 11 — count(A) returns 3. The add happens below the call, so it happens on the way back: that is why the numbers come up the stack.
