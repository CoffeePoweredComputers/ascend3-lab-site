Answer: A — Entry 3, Entry 2, Entry 1, Exit 1, Exit 2, Exit 3 [ASSUMED by tracing; confirm in Runestone]. The Entry print is above the call and the Exit print is below it: the same thing we just saw with count. Step 1 — example(3) is called and prints Entry 3. Step 2 — 3 is more than 1, so it calls example(2) and waits on line 4. Step 3 — Entry 2. Step 4 — example(2) calls example(1) and waits. Step 5 — Entry 1. Step 6 — x is 1, the if is false, so there is no call; example(1) goes straight to its Exit line: Exit 1. Step 7 — example(1) is done; example(2) picks up on the line after its call: Exit 2. Step 8 — example(3) picks up: Exit 3. Step 9 — the wrong answers. C treats each call as if it finished before the next one started, but example(3) is still waiting when example(2) runs. B prints the innermost call first, but Entry 3 prints before any call is made. D has example(2) finishing before example(1) has even started.
