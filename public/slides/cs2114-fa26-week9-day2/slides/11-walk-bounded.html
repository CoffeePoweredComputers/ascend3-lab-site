GENERICS WITH BOUNDS · WALKTHROUGH

A bound on T lets the method call compareTo

A walkthrough of a generic method under a program-counter bar: static T, boolean isSorted of T array a; for int i from 0 while i plus 1 is less than a dot length; if a of i dot compareTo of a of i plus 1 is greater than 0, return false; after the loop, return true. On the right, the call being run, a pill naming the type T, the array as cells, a ring around the two entries being compared and the result. Step one: compareTo is marked in maroon and a plate says cannot find symbol compareTo, because with T alone the compiler knows only Object's methods. Step two: the first line becomes static T extends Comparable of T, with the bound in orange, and the error plate goes away. Step three: isSorted of an Integer array 3, 5, 9; T is Integer; the ring is on 3 and 5, and 3 dot compareTo of 5 is minus 1. Step four: the ring moves to 5 and 9; minus 1 again. Step five: the loop ends and the method returns true. Step six: isSorted of a String array pear, apple; T is String; pear dot compareTo of apple is 15. Step seven: the method returns false. Step eight: isSorted of an Object array does not compile, shown in a maroon plate, because Object does not implement Comparable. Step nine: the bound lets one isSorted work for Integer, String and every other class that implements Comparable.

isSorted, a generic method

  1. static <T>static <T extends Comparable<T>>
  2. boolean isSorted(T[] a) {
  3. for (int i = 0; i + 1 < a.length; i++)
  4. if (a[i].compareTo(a[i + 1]) > 0)
  5. return false;
  6. return true;
  7. }

With <T> alone, T can be any class, so the compiler allows only Object’s methods on a[i]. Object has no compareTo.

With <T extends Comparable<T>>, every T has compareTo(T), so line 4 compiles.

On an Integer[], T is Integer. 3.compareTo(5) is -1, which is not greater than 0.

i is 1. 5.compareTo(9) is also -1.

i + 1 is 3, which is not less than 3, so the loop ends and the method returns true.

On a String[], T is String. "pear".compareTo("apple") is 15, because p comes 15 letters after a.

15 is greater than 0, so the method returns false.

The call with an Object[] does not compile, because Object does not implement Comparable.

The bound lets one isSorted work for Integer, String and every other class that implements Comparable.

The 9.2 module calls this a bounded type parameter: <typeParameterName extends UpperBound>. The video’s own example is add(T first, T second) with <T extends Number>, which calls doubleValue(); the idea is the same as here. (That example’s println concatenates strings, so add(3, 4) prints “Sum = 3.04.0”; worth knowing if a student asks.)
