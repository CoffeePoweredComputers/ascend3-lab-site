This is the table from the Efficiency of List Implementations video. Its column heads are “Array Implementation”, “Singly-Linked Chain Implementation with Head Reference” and “Singly-Linked Chain Implementation with Head and Tail Reference”. Where a cell has three costs, they are for the first, middle and last position. Step 1. add at the end: the array writes into the next free slot; a chain with only a head walks to the last node; the tail reference makes it one step. Step 2. add at a position: the array shifts every entry after the position, so it is cheap only at the end; the chain is cheap only where it already holds a reference. Step 3. toArray visits every entry in every design. Step 4. remove at a position, Vote 2’s row: the array shifts entries left, so only the last position is O(1). Both chains are O(1) only at the front. The tail reference does not help, because removing the last node needs the node before it. Step 5 and step 6. replace and getEntry: the array reads any index in one step; a chain walks to the position, except the head, and the tail when there is one. Step 7. contains searches in every design. Step 8. clear, getLength and isEmpty are one step everywhere. A doubly linked list with a tail reference would change the last cost of remove to O(1), as the doubly linked row on the last slide showed; the video has no such column. Next is Part 3.
