A DOUBLY LINKED LIST · WALKTHROUGH

Two statements remove a middle node, with no search

A walkthrough under a program-counter bar of two statements, each written on two lines: curr dot getPrevious, dot setNext of curr dot getNext; then curr dot getNext, dot setPrevious of curr dot getPrevious. On the right, a doubly linked list of three nodes, A, B and C, each a box with three parts: prev, data and next. Next arrows arc above the chain and prev arrows below it. A blue pill labelled firstNode points at A, a blue pill labelled lastNode points at C, and an orange pill labelled curr, below the chain, points at B. Step one: curr refers to B, the middle node. Step two: the first statement runs; A's next part is washed orange and A's next arrow swings over B to C. Step three: the second statement runs; C's prev part is washed orange and C's prev arrow swings under B to A. Step four: no node in the list refers to B; B, its two arrows and curr fade out. Step five: the removal needs no search, because curr refers to the node and its prev refers to the node before it.

remove curr from the middle

  1. curr.getPrevious()
  2. .setNext(curr.getNext());
  3. curr.getNext()
  4. .setPrevious(curr.getPrevious());

curr refers to B, the middle node. B’s prev is A and B’s next is C.

curr.getPrevious() is A. A’s next is set to curr.getNext(), which is C.

curr.getNext() is C. C’s prev is set to curr.getPrevious(), which is A.

No node in the list refers to B now. When the method returns, nothing refers to B.

The removal needs no search, because curr refers to the node and its prev refers to the node before it.

Every node now has prev, data and next. next arrows are drawn above the chain and prev arrows below it, as in the deque last week. The method names are the ones in today’s first vote: getPrevious, setNext, getNext and setPrevious. Each statement is written on two lines so the code fits beside the drawing. Step 1. curr refers to B. Something found B before this code runs, for example a loop, or an iterator, which is next week. Step 2. curr.getPrevious() is A, so this line sets A’s next to curr.getNext(), which is C. Walking forward from A now skips B. Step 3. curr.getNext() is C, so this line sets C’s prev to A. Walking backward from C now skips B. Step 4. B still refers to A and C, but nothing in the list refers to B, and when the method returns curr is gone too. Step 5. In a singly linked list the method had to walk to the node before B. Here B’s prev gives that node in one step. Ask the room what happens if curr is A. That is the next slide.
