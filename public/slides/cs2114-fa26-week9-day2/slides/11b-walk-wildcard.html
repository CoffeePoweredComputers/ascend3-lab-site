Comparator<? super T> accepts a Comparator for T or for any superclass of T.

ByNum is a Comparator<Number>. It compares any two Numbers by their doubleValue().

a is an Integer[] and d is a Double[].

In sort(a, new ByNum()), T is Integer. Number is a superclass of Integer, so ByNum fits Comparator<? super Integer>.

sort compares the Integers with ByNum, and a becomes 2, 5, 9.

In sort(d, new ByNum()), T is Double. Number is a superclass of Double too.

The same ByNum sorts d, which becomes 0.5, 2.5.

? super T lets one Comparator<Number> sort both arrays, because Number is a superclass of Integer and of Double.

The 9.2 video ends with this declaration: public static <T> void sort(T[] items, Comparator<? super T> comp). Its callouts say that T should also appear in the parameter list, and that comp must implement Comparator for type T or for a superclass of type T, “for example, you can define a class that implements Comparator<Number> and use it to sort an array of Integer objects or an array of Double objects.” ByNum and the two arrays are ours. Comparator is next week’s topic; for today, a Comparator has one method, compare(x, y), that returns a negative number, zero or a positive number, like compareTo.
