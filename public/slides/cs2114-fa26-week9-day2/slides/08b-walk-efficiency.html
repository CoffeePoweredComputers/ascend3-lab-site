remove(0) sets firstNode to B. It visits only A, so the first position is O(1).

remove(2) on the same five nodes. getNodeAt(1) visits A and B to find B, the node before C.

B’s next is set to D. The walk grows with the position, so the middle is O(n).

remove(4) needs D. lastNode refers to E, not D, so getNodeAt(3) visits A, B, C and D.

D’s next is set to null and lastNode to D. That is n − 1 visits, so the last is O(n).

In a doubly linked list, lastNode.getPrevious() is D, so the last is O(1).

Answer: C — O(1); O(n); O(n); [key assumed from the PrairieLearn twin u11q07_list_lastnoderef_c; confirm in Runestone’s results view]. The code is the deck’s own remove, with short names: p is givenPosition, b is the node before, n is numberOfEntries. Positions start at 0, as in the video’s getNodeAt. It leaves out the return value and the case where the list becomes empty. The counter counts the nodes visited to find the node the method has to change. Step 1. Removing the first node only moves firstNode. One visit, for any length, so O(1). Step 2. For the middle, the method needs the node before, B, and the only way to reach B is to walk from firstNode. Step 3. B’s next is set to D. The walk is about n/2 visits for a middle position, which is O(n). Step 4. This is the trap that gives B as an answer. lastNode refers to E, but removing E means changing D’s next, and a singly linked node has no reference back to D. So the walk is from A to D, n − 1 visits. Step 5. D’s next is set to null and lastNode to D. O(n). Step 6. In a doubly linked list with firstNode and lastNode, the last node’s prev is the node before it, so the last position is O(1); that is the sister question in PrairieLearn. The middle is still O(n) in both, because something has to walk to the position. Step 7. The answer is C. lastNode makes add at the end O(1), because adding needs only the last node.
