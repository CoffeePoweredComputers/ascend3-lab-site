Selection sort moves the least. Insertion sort compares the least when the input is nearly in order.

This table collects the counts from the walks. Step 1: insertion sort’s worst case is input in reverse order. Pass i then compares and shifts i times, so the total is 1 + 2 + … + (n − 1) = n(n − 1)/2 of each, which is O(n²). On Vote 1’s input the walk made 10 compares and 9 shifts, close to the worst case of 10 and 10. Step 2: on input that is already in order, each pass makes one compare and no shift, n − 1 compares in all, which is linear. Step 3: selection sort makes n(n − 1)/2 compares whatever the order, because findSmallest always scans the whole unsorted part. It makes one swap call per pass, n in all, and each swap is three assignments. Step 4: Java’s library sorts, Arrays.sort and Collections.sort, are O(n log n). The class writes these two sorts to see where the cost comes from. Step 5: if moving an entry is expensive, selection sort moves the least.
