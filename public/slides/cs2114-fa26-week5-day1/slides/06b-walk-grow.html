ArrayBag.add — when the array can grow

  1. public boolean add(T newEntry) {
  2. if (isArrayFull()) {
  3. doubleCapacity();
  4. }
  5. contents[numberOfEntries] = newEntry;
  6. numberOfEntries++;
  7. return true;
  8. }
  9. private void doubleCapacity() {
  10. T[] bigger = (T[]) new Object[2 * contents.length];
  11. for (int i = 0; i < numberOfEntries; i++) {
  12. bigger[i] = contents[i];
  13. }
  14. contents = bigger;
  15. }
  1. O(1)
  2. O(n)
  3. O(n^2)
  4. Negligible

i = 1 to 5: the other five. Six copies for six entries — n moves.

Answer: B — and the code that grows the array is the argument. Step 1: is it full? Six of six, yes; one compare. Step 2: into the helper. Step 3: a new array twice as long — twelve slots, all null. Steps 4 and 5: the copy loop; watch the entries travel. One copy per entry, so six copies here and n in general — this is the loop that makes the answer. Step 6: contents now refers to the new array; the old one has no name and is garbage. Step 7: back in add, the write we counted in Part 1, slot 6. Step 8: the count. Step 9: eleven moves, six of them copies. Say the two cases plainly: with room, add is three moves, the Week 3 answer; when the array is full, it is n copies and then those three. Big-O names the worst case, so add on a bag that can grow is O(n).
