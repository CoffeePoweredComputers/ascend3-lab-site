Answer: C (instructor-confirmed). The other four options, one per press. The counter starts again at 0 for every run. Step 1, B: exit when list[index].compareTo(anEntry) < 0. Run it for 12, which is in the list. The first entry, 3, is smaller than 12, so compareTo is negative and the loop exits at once. contains returns false for an entry that is there. B has the test backwards: in a sorted list the entries before the position are smaller, so a smaller entry is the reason to keep going. Step 2, D: the same loop from the last index down to 0. For 9 it compares 30, 24, 20, 15, 12, 8, 5 and 3. Larger entries are found sooner, smaller ones later, and a miss is still eight compares. Step 3, E: check both ends and move inwards. Each pass compares two entries, so the four passes make eight compares. Step 4, A: indexOf is a helper that runs the same loop and returns the position, or a negative number when the entry is not there. Calling it changes where the loop is written, not how many compares it makes. Step 5: C is the only option that uses the order. Next is Part 2.
