getPosition calls getEntry up to n times. On a linked list each getEntry walks from firstNode, which gives the sum from Week 10’s Vote 1.

On an array the order also allows a search that halves the range each step. That search is binary search, O(log n), in Week 14.

This is the cost of three of the designs from last week’s Vote 2, from the textbook’s Figure 16-9. Step 1: add(newEntry). Written from scratch on a chain, add walks once with getNodeBefore, so it is O(n). With composition over an array-based list, getPosition is O(n) because each getEntry is O(1), and the add that shifts entries is O(n), so add is O(n). With composition over a linked list, getPosition calls getEntry up to n times and each getEntry walks from firstNode, so add is O(n²). Step 2: contains and getPosition have the same costs for the same reason. Step 3: that walk is Week 10’s Vote 1: get(0), get(1) and so on, each from firstNode, 1 + 2 + … + n visits. Composition takes the least new code, and on a linked list it is the slowest. Step 4: on an array, the order also makes a faster search possible. Binary search looks at the middle entry and keeps the half where the entry must be. That is Week 14. Next is the calendar for Day 2.
