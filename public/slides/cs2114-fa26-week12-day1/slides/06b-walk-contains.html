the body of contains(T anEntry) for a SortedList

  1. boolean found = false;
  2. boolean past = false;
  3. int index = 0;
  4. while (!found && !past && (index < numberOfEntries)) {
  5. int c = list[index].compareTo(anEntry);
  6. if (c == 0) found = true;
  7. else if (c > 0) past = true;
  8. else index++;
  9. }
  10. return found;

Answer: C (instructor-confirmed) — exit the loop when list[index].compareTo(anEntry) > 0, because once the loop has passed the position where the entry would be, the entry cannot appear later. The code is the deck’s own: the 11.2 module describes the early stop in words only, and the course ships no sorted contains. It shows the body of contains; the signature is the same as on the last slides. The counter counts calls to compareTo. Step 1: past is a new flag that records that the loop has gone past where anEntry would be. Steps 2 to 4: 3, 5 and 8 are smaller than 9, so compareTo returns a negative number and index goes up. Step 5: 12 is larger than 9. compareTo returns a positive number, and past is set to true. Step 6: the while test fails on !past, and contains returns false. Four compares instead of eight: the list is sorted, so every entry after 12 is at least 12, and 9 cannot be among them. On average a miss now stops about halfway, which is what “may run faster in the average case” means; the worst case, an entry larger than all of them, is still n compares. Step 7: contains(12) stops on 12 with c equal to 0 and found true, after the same four compares as on the hit slide. A hit is not slowed down. Next: the four other options.
