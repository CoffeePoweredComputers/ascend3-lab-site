Two or more coders code the same items independently, compare, fix the codebook, and repeat on new items. Wiki: [inter-rater reliability](/wiki/qualitative/inter-rater-reliability).

## One round

1. The lead creates a round of 15 to 25 items for two or more coders.
2. Each coder codes every item alone, then submits. Submitting locks the codes.
3. The lead closes the round. Until then nobody sees anyone else's codes.
4. Open **Agreement**, then **Review**.
5. For each disagreement, agree what the item should be. Whoever is driving saves it as the consensus.
6. Change the codebook so it does not recur. Publish. Run the next round.

## While coding

- Each choice has a key. **Enter** saves and deals the next card. **←** goes back.
- Open **Definitions** under a question when unsure. Code what is on the page.
- If two codes fit, use "exclude when". If that does not settle it, pick one and leave a note.
- If nothing fits, leave a multi-label dimension empty or choose "unclear".

## Reading the table

- **Raw agreement**: share of items coded the same. Inflated when a code is rare.
- **κ** (two coders) and **α** (any number): corrected for chance. Report α.
- **AC1**: more stable for rare codes. Check it when raw agreement is high and α is low.
- **Undefined**: only one answer was given, so there is nothing to measure.

Many teams aim for α of 0.8 and treat 0.67 to 0.8 as usable with caution.

## Why coders differed

| Cause | Fix |
| --- | --- |
| Read the definition differently | Rewrite it. Add "exclude when". |
| Two codes overlap | Merge them or draw the line. |
| The item is ambiguous | Add a rule for ambiguous cases. |
| Someone missed something | No change. |
| One code does two jobs | Split it. |

## If a code stays weak

The page lists the codes that were weak in the last round. For each, choose one:

- rewrite its definition, and try it in the next round
- fold it into a neighbouring code
- drop it
- accept it, and say so when you report

## Stop when

Agreement has held for two rounds on new items and one round has passed with no codebook change. The lead then opens Production. The latest codebook version must have been through a round.
